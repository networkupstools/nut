NHS_SER(8)
==========

NAME
----

nhs_ser - Driver for NHS Nobreaks, senoidal line, with serial port

SYNOPSIS
--------

*nhs_ser* -h

*nhs_ser* -a 'UPS_NAME' ['OPTIONS']

NOTE: This man page only documents the hardware-specific features of the
*nhs_ser* driver.  For information about the core driver, see
linkman:nutupsdrv[8].

SUPPORTED HARDWARE
------------------

*nhs_ser* supports numerous UPS models made by NHS Sistemas Eletronicos LTDA
and marketed in Brazil. They feature a serial port and a binary wire protocol.

NOTE: Currently this driver only builds on Linux. This is expected to change
in future revisions of the code.

EXTRA ARGUMENTS
---------------

This driver also supports the following optional settings:

*baud*='num'::
Set the serial port baud rate. The value must be one of the rates available
in the current build (default: 2400).

*serial_data_bits*='num'::
Set the number of data bits to 5, 6, 7, or 8 (default: 8).

*serial_parity*='value'::
Set serial parity to `none`, `even`, or `odd` (default: `none`).

*serial_stop_bits*='num'::
Set the number of stop bits to 1 or 2 (default: 1).

*serial_flow_control*='value'::
Set serial flow control to `none`, `hardware`, `software`, or `both`
(default: `none`). The manufacturer's protocol document specifies 2400
baud, 8 data bits, no parity, 1 stop bit and no handshaking, and that is
what the driver uses unless told otherwise. Earlier versions defaulted to
`hardware`; with it, a port that never raises its "clear to send" line
(some USB CDC-ACM bridges, or a 3-wire serial cable) blocks the request
that starts the communication, and the UPS stays silent. Set `hardware`
only if your installation relied on it.

*serial_read_timeout_ms*='num'::
Set the timeout for reading each byte, in milliseconds. Values from 0 to
60000 are accepted; 0 requests a non-blocking read (default: 100).

*serial_send_pace_us*='num'::
Set the delay between transmitted bytes, in microseconds. Values from 0 to
999999 are accepted; 0 disables transmission pacing (default: 0).

The driver has built-in data for each model code that the UPS may report.
For part of the models it holds the nominal power in W, the full-load
efficiency and the capacity of the factory batteries, as published in the
manufacturer's product sheets. Every value is resolved in the same order:
the setting in `ups.conf`, then the data of the reported model, then the
"unknown device", which holds the driver's defaults and also answers for a
model code that the driver does not know. A rating that is still unknown
after that does not stop the driver; the variables that depend on it are
simply not published.

NOTE: Data from one UPS is never used for another. Whenever the serial port
is reopened the driver asks the UPS to identify itself again, and if the
answer shows a different unit (another model code, hardware version,
firmware version, number of batteries or serial number) everything learned
from the previous one is discarded: its ratings, the minimum and maximum
power statistics and the variables that depended on them. The driver then
starts over for the new unit, as after a restart, and logs a notice. Two
units that answer exactly alike, as units of the same model without a
serial number do, cannot be told apart: restart the driver after swapping
such units.

The next six settings replace the built-in value for the UPS being
monitored; use them when the driver has no value for your model, or when
your unit differs from it (for example after fitting batteries of another
capacity). A value that is not a number inside the accepted range stops
the driver at startup.

*ah*='num'::
Capacity of each battery, in Ampere-hour (a positive integer). It is always
the capacity of ONE battery, however many there are and whether they are
wired in series or in parallel (see *numbatteries* and *battery_series*).
When neither this setting nor the model data provides a capacity, the
driver does not publish `battery.capacity` nor `battery.runtime`.

*va*='num'::
Nominal power in VA. Needed for models whose code the driver does not
know: without a value from either source the driver keeps running and
does not publish the power and runtime variables. Earlier versions exited
with an error in that case.

*pf*='num'::
Power factor, that is the nominal power in W divided by the nominal power
in VA, from 0.01 to 1. It is used to calculate the real power and the
battery runtime. Without this setting and without a value for the model,
the driver uses 0.90; most NHS line-interactive models are rated 0.5 or
0.6.

*efficiency_line*='num'::
Efficiency at full load while on mains, with the input and the output at
the same nominal voltage, as a percentage from 1 to 100.

*efficiency_line_conv*='num'::
Efficiency at full load while on mains, when the UPS converts between
120V and 220V, as a percentage from 1 to 100. When unknown, the value of
*efficiency_line* is used.

*efficiency_inverter*='num'::
Efficiency at full load while on battery, as a percentage from 1 to 100.

NOTE: `ups.efficiency` is the manufacturer's full-load rating for the
current operating mode, chosen among the three values above. The NHS
protocol does not report input power or current, so the driver cannot
measure the efficiency; when no rating is known the variable is not
published.

NOTE: `battery.current` and `battery.current.total` are estimates, since
the UPS does not report them. While the UPS runs on battery, the first is
the current through each battery: the load in W divided by the inverter
efficiency, by the number of batteries and by the voltage of one battery.
The second is the current of the whole bank: the same figure when the
batteries are in series, or that figure times the number of batteries when
they are in parallel (see *battery_series*). On mains both are 0, as the
batteries are not supplying the load. They are also 0 while the driver
lacks what it needs to calculate them (the nominal power, the number of
batteries or a voltage reading). Earlier versions published the on-battery
figures at all times, without the inverter losses, and a total that was
always multiplied by the number of batteries.

NOTE: `battery.runtime` is an estimate, since the UPS does not report it.
The load in W is divided by the inverter efficiency (80% is assumed when
the model has no known rating) to get the power taken from the batteries;
that power is shared by all the batteries, and the time each one lasts at
its current is worked out with Peukert's law, because a lead-acid battery
delivers much less than its nominal capacity when it is emptied in minutes
instead of hours. The calculation was adjusted against the runtimes that
the manufacturer declares for 110 products, and falls within one third of
the declared figure in most cases. It depends on *ah*, *numbatteries*,
*vbat*, *pf* and *efficiency_inverter* being right for your unit, it
describes batteries in good condition, and it does not count down during a
discharge: it changes only with the load. While the UPS reports no load at
all, or when the battery capacity is not known, there is nothing to
calculate from and the variable is not published; earlier versions kept
showing the last value calculated. The low battery condition (`LB`) still
comes from the UPS itself.

The next four settings are margins, in percent, used to derive the input
voltage thresholds from the two transfer points that the UPS reports
(`input.transfer.low` and `input.transfer.high`). A margin is always taken
toward the normal range: added to the low transfer point, subtracted from
the high one. This way a voltage leaving the normal range crosses the
warning threshold first, then the critical one, and only then the point
where the UPS goes to battery. When the warning and the critical margins of
one side are equal, as with the defaults, the warning margin is doubled.

*vin_low_warn_perc*='num'::
Margin above the low transfer point for `input.voltage.low.warning`
(default: 2.00).

*vin_low_crit_perc*='num'::
Margin above the low transfer point for `input.voltage.low.critical`
(default: 2.00).

*vin_high_warn_perc*='num'::
Margin below the high transfer point for `input.voltage.high.warning`
(default: 2.00).

*vin_high_crit_perc*='num'::
Margin below the high transfer point for `input.voltage.high.critical`
(default: 2.00).

*numbatteries*='num'::
Number of batteries (a positive integer). It replaces the count reported
by the UPS, which is what to use when the battery set was changed from
the factory one.

*battery_series*='0|1'::
How the batteries are wired to each other: 1 when they are in series, 0
when they are in parallel. The driver knows the factory wiring of part of
the models and takes the others as wired in series, which is how nearly
every NHS model is built. Set it when the batteries of your unit were
wired differently from the factory set. It is used for
`battery.current.total`: in series the bank carries the current of one
battery, in parallel that current times the number of batteries.

*overload_perc*='num'::
Load, in percent of the nominal power, above which the driver reports the
UPS as overloaded (`OVER` in `ups.status`). The UPS has no flag of its own
for this, only the load reading. The default is 105, the limit used by the
manufacturer's monitoring software; 0 turns the check off.

The next six settings choose how each two-byte reading sent by the UPS is
decoded, one setting for each reading. With 0, the default, the two bytes
are taken as an integer part and a fraction, which is what the
manufacturer's protocol document describes and what the driver has always
done. With 1 they are taken as one 16-bit number (first byte plus 256
times the second), which is what the manufacturer's own monitoring
software does. Both give the same value up to 255 (25.5V for the battery
voltage) and differ above that, so these settings only matter for a unit
that reports larger values: for example an input voltage of 260V, or a
battery reading of more than 25.5V.

*read16_vin*='0|1'::
Input voltage.

*read16_vin_min*='0|1'::
Minimum input voltage.

*read16_vin_max*='0|1'::
Maximum input voltage.

*read16_vout*='0|1'::
Output voltage.

*read16_temp*='0|1'::
Temperature.

*read16_vbat*='0|1'::
Battery voltage, which the UPS sends in tenths of a volt.

*vbat*='num'::
Nominal voltage of ONE battery, in V (default: 12.00). Every NHS model
uses 12V batteries, so this should hardly ever be set; in particular, do
not put the voltage of the whole bank here. It is meant for units whose
batteries were replaced by another kind, together with *numbatteries* and
*ah*, and it accepts decimals (for example 12.8 for a lithium iron
phosphate battery). Depending on the model, the
UPS reports the voltage of a single battery or of a set of them, and the
driver tells which from the reading itself: `battery.voltage` is the
reading as reported, `battery.voltage.nominal` is this value times the
number of batteries that the reading covers, and `battery.charge` places
the reading on a scale drawn from that nominal voltage (see the note
below).

NOTE: `battery.charge` is an estimate from the battery voltage, since the
UPS does not report a charge. It is a straight scale from 0% at 10.5V for
each 12V battery, the voltage at which a lead-acid battery is taken as
empty, to 100% at 12.6V, its voltage when full and at rest; both follow
*vbat* in proportion. Earlier versions divided the reading by the nominal
voltage, which only went from 100% to 87% over a complete discharge. The
voltage of a battery also falls with the load and rises while the charger
is working, and it drops faster near the end of a discharge than at the
beginning, so read the value as how far the battery is from empty and not
as an exact share of the time left.

*overridemodel*='string'::
Replace the model name published as `device.model` and `ups.model`.
A non-empty string overrides the detected model name; the driver stores
at most 99 bytes of the supplied name. An empty value leaves the model
name unchanged.

*bypassasalarm*='0|1'::
Control whether the decoded bypass bit produces an `[ON BYPASS]` alarm.
The default value is 0. On most units checked so far the UPS sets this bit
for as long as it runs normally from mains and clears it only while it runs
from the inverter: it means that the load is fed from mains, not that
something failed. Treating it as an alarm reported a healthy UPS as `ALARM`
all the time, which earlier versions of the driver did by default. Some
models keep the bit clear on mains instead. Set this to 1 only after
checking, for example with the *debug_pkt_data* flag, that on your unit
the bit is clear in normal operation and marks a real bypass condition.
The decoded bit remains available in packet diagnostics either way.

NOTE: Earlier versions also raised the alarms `[220V IN]` and `[220V OUT]`
whenever the input or the output of the UPS was at 220V, which left every
unit fed from 220V mains with a permanent `ALARM` status. Working at 220V
is not a fault and these alarms are no longer raised. The voltages are
reported in `input.voltage.nominal` and `output.voltage.nominal`.

*debug_pkt_raw*::
Optional flag to enable debug logging of packet bytes.

*debug_pkt_data*::
Optional flag to enable debug logging of data packet decoding.

*debug_pkt_hwinfo*::
Optional flag to enable debug logging of hwinfo packet decoding.
