[[Start_here_preparation]]
Before you start
~~~~~~~~~~~~~~~~

Use the manuals for your installed NUT version. For package installations,
follow the package instructions for file locations and service management.
The website also provides
link:https://networkupstools.org/historic/[documentation for selected historic releases].

Identify which computers receive power from the UPS and which computer
communicates with it. NUT uses three components:

* A *driver* communicates with a power device using its supported protocol.
* *upsd* runs on the same host as the driver and serves its data to clients.
* *upsmon* monitors power conditions and initiates shutdown of its own host.
  It connects to `upsd` over TCP, even when both run on the same host.

For multiple UPSes, redundant supplies or different communication and power paths,
read the
ifdef::website[]
link:docs/user-manual.chunked/Configuration_notes.html#DataRoom[deployment descriptions]
endif::website[]
ifndef::website[]
<<DataRoom,deployment descriptions>>
endif::website[]
and
ifdef::website[]
link:docs/user-manual.chunked/Configuration_notes.html#BigServers[redundant-power guidance]
endif::website[]
ifndef::website[]
<<BigServers,redundant-power guidance>>
endif::website[]
before choosing a setup.

[[Start_here_local]]
Set up a UPS connected to this computer
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

This path covers one computer powered by one UPS, with a local USB or serial
communication connection to that UPS. The computer needs a driver, `upsd`
and `upsmon` for automatic shutdown protection.

. *Choose a driver.* Check
ifdef::website[]
link:stable-hcl.html[hardware compatibility]
endif::website[]
ifndef::website[]
<<HCL,hardware compatibility>>
endif::website[]
  and read the selected driver's manual for connection settings and limitations.
. *Choose the installation and startup method.* Use your package instructions,
  or the
ifdef::website[]
link:docs/user-manual.chunked/_installation_instructions.html[source installation instructions]
endif::website[]
ifndef::website[]
<<_installation_instructions,source installation instructions>>
endif::website[]
  when building NUT yourself. Read
ifdef::website[]
link:docs/user-manual.chunked/Configuration_notes.html#_startup_integration[startup integration]
endif::website[]
ifndef::website[]
<<_startup_integration,startup integration>>
endif::website[]
  before starting processes; do not start a second manual copy of a
  service-managed driver or daemon.
. *Establish device communication.* Follow
ifdef::website[]
link:docs/user-manual.chunked/Configuration_notes.html#Driver_configuration[driver configuration]
endif::website[]
ifndef::website[]
<<Driver_configuration,driver configuration>>
endif::website[]
  and then
ifdef::website[]
link:docs/user-manual.chunked/Configuration_notes.html#_data_server_configuration_upsd[data server configuration].
endif::website[]
ifndef::website[]
<<_data_server_configuration_upsd,data server configuration>>.
endif::website[]
. *Check the readings.* Follow
ifdef::website[]
link:docs/user-manual.chunked/Configuration_notes.html#_check_the_ups_data[checking UPS data]
endif::website[]
ifndef::website[]
<<_check_the_ups_data,checking UPS data>>
endif::website[]
  and compare the reported status with the device's actual condition.
. *Configure shutdown protection.* Follow
ifdef::website[]
link:docs/user-manual.chunked/Configuration_notes.html#UPS_shutdown[automatic shutdown configuration]
endif::website[]
ifndef::website[]
<<UPS_shutdown,automatic shutdown configuration>>
endif::website[]
  for the monitoring account, `upsmon` configuration and shutdown integration.
  In this simple topology, this host's `upsmon` is the primary for the UPS.
. *Test shutdown.* Read
ifdef::website[]
link:docs/user-manual.chunked/Configuration_notes.html#_checking_upsmon[checking upsmon]
endif::website[]
ifndef::website[]
<<_checking_upsmon,checking upsmon>>
endif::website[]
  and
ifdef::website[]
link:docs/user-manual.chunked/Configuration_notes.html#Testing_shutdowns[testing shutdowns].
endif::website[]
ifndef::website[]
<<Testing_shutdowns,testing shutdowns>>.
endif::website[]
  Schedule the forced shutdown test for a time when all protected systems
  can be shut down. Check the shutdown, power-off and restart steps.

[[Start_here_network]]
Protect another computer using an existing NUT server
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

For a computer powered by a UPS already managed by a NUT server and primary
monitor, install `upsmon` and configure it as a secondary. It connects to
the existing server over the network.

. *Identify the power source and server.* Obtain the UPS name, server address
  and port, and monitoring credentials from the server administrator. Confirm
  that this is the UPS supplying the additional computer.
. *Prepare the server side.* Review the listening addresses in
ifdef::website[]
link:docs/man/upsd.conf.html[upsd.conf(5)],
endif::website[]
ifndef::website[]
linkman:upsd.conf[5],
endif::website[]
  the monitoring account and secondary permissions in
ifdef::website[]
link:docs/man/upsd.users.html[upsd.users(5)],
endif::website[]
ifndef::website[]
linkman:upsd.users[5],
endif::website[]
  and the
ifdef::website[]
link:docs/user-manual.chunked/NUT_Security.html[security guidance].
endif::website[]
ifndef::website[]
<<NUT_Security,security guidance>>.
endif::website[]
. *Check data access from the additional computer.* Use the status-query
  guidance in
ifdef::website[]
link:docs/man/upsc.html[upsc(8)].
endif::website[]
ifndef::website[]
linkman:upsc[8].
endif::website[]
. *Configure the additional computer's monitor.* Follow
ifdef::website[]
link:docs/user-manual.chunked/Configuration_notes.html#_create_a_monitor_directive_for_upsmon[the MONITOR configuration]
endif::website[]
ifndef::website[]
<<_create_a_monitor_directive_for_upsmon,the MONITOR configuration>>
endif::website[]
  and
ifdef::website[]
link:docs/man/upsmon.conf.html[upsmon.conf(5)]
endif::website[]
ifndef::website[]
linkman:upsmon.conf[5]
endif::website[]
  for the secondary role, local shutdown command and configuration permissions.
  Follow the package's
ifdef::website[]
link:docs/user-manual.chunked/Configuration_notes.html#_startup_integration[startup integration].
endif::website[]
ifndef::website[]
<<_startup_integration,startup integration>>.
endif::website[]
  For packages that use
ifdef::website[]
link:docs/man/nut.conf.html[nut.conf(5)],
endif::website[]
ifndef::website[]
linkman:nut.conf[5],
endif::website[]
  set `MODE=netclient` on the additional computer. Each computer's `upsmon`
  handles that computer's shutdown.
. *Check monitoring and coordinated shutdown.* Use
ifdef::website[]
link:docs/user-manual.chunked/Configuration_notes.html#_checking_upsmon[monitor login checks]
endif::website[]
ifndef::website[]
<<_checking_upsmon,monitor login checks>>
endif::website[]
  first. Coordinate
ifdef::website[]
link:docs/user-manual.chunked/Configuration_notes.html#Testing_shutdowns[shutdown testing]
endif::website[]
ifndef::website[]
<<Testing_shutdowns,shutdown testing>>
endif::website[]
  with the administrator of the UPS and all affected systems. These tests
  shut down the protected computers.

[[Start_here_troubleshooting]]
Troubleshoot an existing installation
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Start with the component and symptom involved. A client connection, a fresh
device reading and a successful monitor login establish different things.

* *The driver cannot open the device:* read the
ifdef::website[]
link:docs/FAQ.html#FAQ_driver_permissions[driver permissions FAQ]
endif::website[]
ifndef::website[]
linksingledoc:FAQ[driver permissions FAQ,FAQ_driver_permissions]
endif::website[]
  and the selected driver's manual. Drivers normally drop root privileges
  before opening the device.
* *A client cannot connect to upsd:* start with the
ifdef::website[]
link:docs/FAQ.html#FAQ_server_connection[server connection FAQ]
endif::website[]
ifndef::website[]
linksingledoc:FAQ[server connection FAQ,FAQ_server_connection]
endif::website[]
  and the configured listening addresses. For an access-denied response,
  follow the separate
ifdef::website[]
link:docs/FAQ.html#FAQ_access_denied[access-control FAQ].
endif::website[]
ifndef::website[]
linksingledoc:FAQ[access-control FAQ,FAQ_access_denied].
endif::website[]
* *A client reports "Driver not connected":* follow the
ifdef::website[]
link:docs/FAQ.html#FAQ_driver_not_connected[driver connection FAQ].
endif::website[]
ifndef::website[]
linksingledoc:FAQ[driver connection FAQ,FAQ_driver_not_connected].
endif::website[]
  Check the connection between `upsd` and the driver.
* *A client reports stale data:* follow the
ifdef::website[]
link:docs/FAQ.html#FAQ_data_stale[data freshness FAQ].
endif::website[]
ifndef::website[]
linksingledoc:FAQ[data freshness FAQ,FAQ_data_stale].
endif::website[]
  Check whether the driver is receiving fresh device data.
* *The computer does not shut down as expected:* review
ifdef::website[]
link:docs/user-manual.chunked/Configuration_notes.html#_checking_upsmon[upsmon checks]
endif::website[]
ifndef::website[]
<<_checking_upsmon,upsmon checks>>
endif::website[]
  and the
ifdef::website[]
link:docs/FAQ.html#FAQ_no_shutdown[shutdown conditions FAQ].
endif::website[]
ifndef::website[]
linksingledoc:FAQ[shutdown conditions FAQ,FAQ_no_shutdown].
endif::website[]
* *The computer stays off after UPS power returns:* read the
ifdef::website[]
link:docs/FAQ.html#FAQ_power_return[power-return FAQ].
endif::website[]
ifndef::website[]
linksingledoc:FAQ[power-return FAQ,FAQ_power_return].
endif::website[]

If the problem remains, follow
ifdef::website[]
link:docs/user-manual.chunked/Support_Request.html[the support-request guidance].
endif::website[]
ifndef::website[]
<<Support_Request,the support-request guidance>>.
endif::website[]
Include the NUT version, installation method, device and relevant log excerpts;
remove passwords and other sensitive information before posting them publicly.

Data dumps for the DDL
----------------------

Note: both developers contributing a driver and users using an existing driver
for device not previously documented as supported by it, are welcome to report
new data for the Devices Dumps Library (DDL) mentioned above. Best of all such
"data dump" reports can be prepared by the
ifdef::website[]
link:https://raw.githubusercontent.com/networkupstools/nut/master/tools/nut-ddl-dump.sh[`tools/nut-ddl-dump.sh`]
endif::website[]
ifndef::website[]
`./tools/nut-ddl-dump.sh`
endif::website[]
script from the main NUT codebase, and reported on the NUT mailing list or
via link:https://github.com/networkupstools/nut/issues[NUT issues on GitHub]
or as a pull request against the
link:https://github.com/networkupstools/nut-ddl[NUT Devices Dumps Library]
following the naming and other rules described in the DDL documentation page.

Data dumps collected by the tools above, or by `upsc` client, or by drivers
in exploratory data-dumping mode (with `-d 1` argument), can be compared by
ifdef::website[]
link:https://raw.githubusercontent.com/networkupstools/nut/master/tools/nut-dumpdiff.sh[`tools/nut-dumpdiff.sh`]
endif::website[]
ifndef::website[]
`./tools/nut-dumpdiff.sh`
endif::website[]
script from the main NUT codebase, which strips away lines with only numeric
values (aiming to minimize the risk of losing meaningful changes like counters).
